# Privacy Policy

**Last updated:** October 18, 2026

DevPulse is a VS Code extension that tracks your coding activity locally and
sends it to the DevPulse backend you choose. This document explains exactly
what data is collected, what is not, and how you control it.

## What DevPulse collects

DevPulse collects **metadata about your coding activity**, never the content
of your work.

### Events sent to the backend

| Event                     | What is sent                                                                                         |
| ------------------------- | ---------------------------------------------------------------------------------------------------- |
| `heartbeat`               | Timestamp, current branch, machine ID, VS Code session ID                                            |
| `file_save`               | Relative file path, language ID                                                                      |
| `file_switch`             | Relative file path, language ID                                                                      |
| `idle_start` / `idle_end` | Timestamp, idle duration in milliseconds                                                             |
| `session_end`             | Timestamp, branch                                                                                    |
| `terminal_command`        | Sanitized command text, working directory, exit code, duration                                       |
| `task_run`                | Task name, task source, exit code, duration                                                          |
| `git_commit`              | Commit SHA, commit message, files changed count, lines added/deleted, list of changed files (max 10) |

### Environment fields attached to every event

- `machineId` and `sessionId` — generated by VS Code, not linked to your hardware
- `clientTimestamp`

## What DevPulse does NOT collect

- **File contents.** The extension never reads what you write.
- **Keystrokes.** No keylogger behavior.
- **Terminal output.** Only the command text (sanitized) and exit code.
- **Secrets.** Commands are sanitized before sending:
  - URL credentials (`https://user:pass@host`) are stripped
  - Bearer tokens are replaced with `[REDACTED]`
  - Flags like `--password=`, `--token=`, `--api-key=` are masked
- **Screen or clipboard content.**
- **Your personal identity.** No email, name, or IP is sent by the extension.

## Where data goes

All events are sent over HTTPS to the API endpoint configured in
`devpulse.apiUrl` (default: `http://localhost:3000/api/v1` for local
development). You choose the backend.

The API key that authorizes requests is stored in VS Code SecretStorage
(OS keychain on macOS, Credential Vault on Windows, libsecret on Linux).

## Your controls

- **Workspace trust.** DevPulse only activates in trusted workspaces.
- **VS Code telemetry toggle.** If you disable telemetry globally in VS Code,
  DevPulse stops sending. This is enforced at runtime.
- **Pause / Resume.** `DevPulse: Pause Tracking` from the Command Palette
  stops all collection immediately. Already-buffered events are flushed to
  the backend first, then no more events are sent until you resume.
- **Clear API key.** `DevPulse: Clear API Key` removes the stored key. No
  data will be sent until a new key is configured.
- **Local buffer.** Events are buffered locally (in VS Code `globalState`,
  max 500 events) if the backend is unreachable. You can clear this buffer
  by running `DevPulse: Clear API Key`.
- **Uninstall.** Uninstalling the extension stops all activity. Buffered
  events are discarded.

## Data retention

DevPulse does not control retention — that is entirely the responsibility of
the backend operator (which may be you, in local deployment). The extension
sends data and forgets it.

## Children's privacy

DevPulse is not intended for users under 16.
